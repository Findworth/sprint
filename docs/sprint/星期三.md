# 在经过星期一和二之后，已经确定了最终冲刺目标和一堆解决方案，接下来需要高效挑选解决方案(不可能给所有解决方案都写一个原型)，为后续的原型制作做准备

## 高效筛选解决方案
流程：
    1. 将不同的解决方案都放在白板上，且有一定的间距
    2. 团队内的每个成员都有一些票(不限制成员持有的票的数量)，接下来开始对不同的解决方案投票，在这个过程中，成员之间不得交流，在投票过程中，如果有疑问，则在白板上对应的解决方案下面更新疑问(以笔记的形式)
    3. 团队快速批判不同的解决方案，此时可以相互交流，对每一个解决方案进行批判，不过需要严格遵守时间限制，批判过程中，需要遵守以下原则：
        1. 团队内的所有成员一次只能聚焦在一个解决方案上
        2. 时间限制：根据票数多少来决定时间限制，票数越多，时间限制越长
        3. 引导者宣布该解决方案的出众想法(注意，此时该解决方案的策划者不得发言)
        4. 团队其他成员补充引导者的想法，并将新的补充放到白板上(注意，此时该解决方案的策划者不得发言)
        5. 回顾忧虑和疑问(注意，此时该解决方案的策划者不得发言)
        6. 此时注意该解决方案的策划者可以出面来解答其他成员没有想到的信息，然后重复上述过程，直到所有解决方案都讨论完毕
    4. 进行第二次投票，此时团队内所有成员都只有一票，团队成员之间不得交流，需要完成匿名投票(注意，这里是匿名的)。投票结束之后，每个人才可以继续阐述最终选择的理由
    5. 决策者(也就是领袖)进行最终的投票，此时每个决策者最多有三张票可以投(最多有2个决策者)，可以投的对象包括所有的解决方案
    6. 在决策者投票选择出最终的解决方案之后，如果选择的解决方案不同，首先考虑这些解决方案是否是互斥的，不可结合的，如果互斥，那么制作这些解决方案的原型，如果可结合，那么思考如何将这些解决方案结合在一起
    7. 在决定出解决方案之后，开始制作长篇分镜脚本(也就是设想用户从发现到使用产品的全流程)：
        1. 制作方框：这些方框将存放分镜中的某一个场景，每个方框代表一个场景，场景之间需要有一定的连线，连线代表场景之间的逻辑关系
        2. 第一个镜头：作为长篇分镜的开场，这个开场也就是用户发现产品的场景，比如用户在浏览新闻报刊的时候，在浏览应用商店时，在浏览社交媒体时，比如在看邮箱时，网页搜索时等等情况
        3. 第一个镜头与后续镜头应该遵守的原则：
            1. 应该体现出解决方案中的细节与内容
            2. 整个最后的脚本是一个完整的故事，故事中需要包含用户发现产品，使用产品，解决问题的全流程
            3. 在写镜头应该包含的内容和文案时，应该交给团队中的某一个人负责，只有他有权利写分镜脚本内容，但是他每画一个分镜，都需要和其他成员讨论
            4. 每一个分镜脚本都需要有重点词和标题，在与团队进行讨论时，如果有分歧，最终决策者有最终决策权
            5. 整个脚本大概是一个10-15分钟的故事，所以需要考虑到每个镜头的时间长度，以及场景之间的逻辑关系
